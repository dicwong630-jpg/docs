# 電影製作場景分析

以下從**技術製片（Technical Producer / Production Manager）**的視角，逐點分析龍蝦搬運工如何切入大型電影製作的資料管理痛點。

---

## 一、龍蝦搬運工對大型電影製作流程的直接幫助

<AccordionGroup>
  <Accordion title="1. 大批素材快速分流入倉" icon="box-archive">
    電影製作日均可產生數百至數千個檔案（分鏡圖、美術稿、動態分鏡、渲染圖、AI prompt 包、音效）。龍蝦搬運工的**批量移動 / 複製引擎**可依照預設規則（場景代號、部門、日期）一鍵將素材搬入對應目錄，取代人手逐一拖拉，錯誤率趨近於零。
  </Accordion>

  <Accordion title="2. 跨部門交付自動化" icon="arrow-right-arrow-left">
    導演組、美術組、特效組之間頻繁互相交付工作檔。透過**分類策略插件**，可定義「凡帶有 `VFX_` 前綴且副檔名為 `.exr` / `.psd` 者，自動複製至 `/delivery/vfx/`」，無需協調人員手動整理，也不依賴各部門命名習慣是否一致。
  </Accordion>

  <Accordion title="3. AI Prompt 包管理與版本分流" icon="robot">
    在 AI 輔助製作流程中，每個鏡頭可能對應多版 prompt 及對應生成結果。龍蝦搬運工的**批量標籤功能**可自動為 prompt 包標注版本號、鏡頭代碼、生成模型，方便後期比較與選版，也方便音效、剪接組取用。
  </Accordion>

  <Accordion title="4. 製作節點資料打包一鍵導出" icon="file-zipper">
    週期性里程碑（例如送審版、Preview Screening）需要快速打包指定鏡頭的所有相關素材。批量分類加上未來的**索引目錄自動生成**功能，可讓技術製片在幾分鐘內完成原本需要半天的素材整合工作。
  </Accordion>

  <Accordion title="5. 日誌追蹤，跨地協作有據可查" icon="scroll">
    多地遠端合作（導演在香港、特效在深圳、後期在台北）時，**操作日誌**記錄每次搬運、分類的時間戳、執行者、操作路徑，讓任何人都能快速確認「最新版美術稿在哪裡」、「誰搬走了渲染檔」。
  </Accordion>

  <Accordion title="6. 插件化，靈活接入現有製作管線" icon="plug">
    不同製作公司有不同的命名規範和資產管理系統（如 Shotgrid / ftrack）。龍蝦搬運工的**插件架構**允許在不改動核心的前提下，撰寫針對特定製作管線的對接插件，維護成本低、可重複利用。
  </Accordion>
</AccordionGroup>

## 二、沒有龍蝦搬運工時的製作管理痛點

<Warning>
以下每一項痛點，在大型電影製作中均可能造成**延誤交期、損失素材、追責困難**等後果。
</Warning>

<Steps>
  <Step title="人工操作耗時爆增，重複性勞動佔去製片精力">
    素材整理、改名、分資料夾全靠人手，每天可能耗費技術製片或製片助理 2–4 小時重複性工作。隨製作規模放大，這個問題呈**指數級惡化**。
  </Step>

  <Step title="命名與目錄規範難以強制執行">
    人工整理時，不同成員的習慣不同，導致同一批素材散落於多個不規範路徑，後期剪輯或特效組找檔案要花大量時間，甚至找不到正確版本。
  </Step>

  <Step title="素材流向無可追蹤，責任歸屬模糊">
    沒有操作日誌，「這份分鏡稿是哪個版本？上次誰改了渲染路徑？」這類問題無法系統化追蹤，只能靠人工問詢，浪費溝通成本。
  </Step>

  <Step title="誤操作難以復原，高風險素材可能永久丟失">
    人工批量操作時（如整批重命名或搬移），一旦出錯，沒有撤銷機制就等於永久丟失素材。對不可重拍的場景素材或高成本 CGI 渲染結果，這是災難性風險。
  </Step>

  <Step title="新工作流程（如 AI 輔助製作）無法快速整合">
    AI 生成素材、AI prompt 管理是近年新增的製作環節。沒有插件化工具，每次引入新環節都需要重寫整套整理腳本，技術債迅速累積。
  </Step>

  <Step title="跨部門、跨地域協作摩擦大">
    不同部門之間的素材交付依賴人工溝通（WhatsApp、電郵），效率低且容易遺漏。沒有自動分流規則，遠端團隊成員難以即時取得所需最新素材。
  </Step>

  <Step title="大規模測試與自動化管線無法建立">
    沒有統一的批量處理框架，每個自動化需求（如每晚自動備份最新渲染至 NAS）都要另起爐灶開發，維護成本高，復用性差。
  </Step>
</Steps>

## 三、落地電影製作需優先完善的模組（技術製片視角）

根據現時 1.0 缺失的功能清單，以下按**緊急程度**排列優先完善順序：

<CardGroup cols={1}>
  <Card title="🔴 優先級 1：操作日誌與撤銷（Undo）系統" icon="clock-rotate-left">
    **為何最優先：** 在製作現場，任何批量操作出錯都可能造成不可逆損失。此模組是「安全網」，沒有它，技術製片不敢放心讓工具自動執行批量操作。

    **建議功能：**
    - 記錄每次操作的時間戳、操作類型、來源路徑、目標路徑
    - 支援單步撤銷（undo last operation）和多步撤銷
    - 操作日誌可導出為 CSV / JSON，方便 Production Coordinator 查閱
  </Card>

  <Card title="🔴 優先級 2：格式支持插件強化" icon="file-lines">
    **為何優先：** 電影製作常用格式包括 `.fdx`（Final Draft 腳本）、`.pdf`（分鏡、合約）、`.docx`（場記、人物表）、`.csv`（素材清單）、`.exr` / `.dpx`（高位元深度影像）。若批量處理只支援通用副檔名過濾而無法解析內容，很多自動分類邏輯無從落實。

    **建議功能：**
    - 腳本格式（`.fdx`、`.fountain`）解析插件：提取場景編號、角色名稱作為分類依據
    - PDF 元數據讀取插件：依文件標題或版次自動分類
    - 影像序列識別插件：自動識別 `shot_001_v003.0001.exr` 格式並按鏡頭 / 版次歸類
  </Card>

  <Card title="🟡 優先級 3：自定分類規則配置介面 / 規則腳本" icon="sliders">
    **為何重要：** 不同製作公司的命名規範差異大。硬編碼的分類規則無法跨專案復用。提供 YAML / JSON 規則配置介面，讓非技術人員（如製片助理）也能自訂規則，大大提升工具實用性。

    **建議功能：**
    - 規則配置文件格式定義（YAML / JSON）
    - CLI 命令 `lobster config add-rule` / `lobster config list-rules`
    - 規則語法支援萬用字元、正規表達式、元數據條件
  </Card>

  <Card title="🟡 優先級 4：批量重命名模組" icon="pen-to-square">
    **為何重要：** 電影製作交付時，客戶（電視台、串流平台）往往有嚴格的檔案命名規範。批量重命名是日常高頻操作，必須支援模板化（如 `{project}_{scene}_{shot}_{version}.{ext}`）並提供預覽模式。

    **建議功能：**
    - 模板化重命名規則
    - Dry-run 預覽
    - 與操作日誌整合（可撤銷）
  </Card>

  <Card title="🟢 優先級 5：索引目錄自動生成 / 一鍵導出資料包" icon="folder-tree">
    **為何重要：** 送審版、DCP 交付、備份歸檔時，技術製片需要快速生成一份完整的素材清單及打包目錄。此功能可將原本半天的人工工作壓縮至數分鐘。

    **建議功能：**
    - 掃描指定目錄，生成帶有元數據的索引（Markdown / CSV / HTML）
    - 根據指定規則篩選並打包成 ZIP / tar 資料包
    - 支援「本次變更」增量導出模式
  </Card>

  <Card title="🟢 優先級 6：跨平台 / 雲端同步插件" icon="cloud-arrow-up">
    **為何重要：** 現代電影製作多地協作已是常態。與 Google Drive、Dropbox、AWS S3 或 NAS 的整合可讓龍蝦搬運工成為整個製作管線的樞紐。

    **建議功能：**
    - 插件介面定義（`CloudSyncPlugin` 抽象基類）
    - 官方提供 AWS S3 / Google Drive 範例插件
    - 支援增量同步與衝突偵測
  </Card>
</CardGroup>

## 總結

<Tip>
**技術製片結論：** 龍蝦搬運工不是「便利工具」，而是大型電影製作資料管線的**骨幹基建**。缺少它，製作團隊每天都在用人力補貼工具缺口，既耗時又高風險。

**最優先的三個模組**（可立即解鎖安全生產環境）：
1. 操作日誌 + 撤銷系統
2. 格式支持插件強化
3. 自定分類規則配置介面
</Tip>
